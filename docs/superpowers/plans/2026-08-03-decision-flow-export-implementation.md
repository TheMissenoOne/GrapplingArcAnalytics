# Decision Flow Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish an eligible athlete's existing compiled Decision Flow as optional `AthleteDossierV1.decisionFlow` data.

**Architecture:** `build_style_profile()` remains source of aggregated raw patterns. A narrow adapter in `analysis/dossier_decision_flow.py` reconstructs `DecisionPattern`/`PatternEvidence`, infers the existing root, and delegates to `build_decision_flow_from_patterns()`; the dossier builder only attaches a non-`None` result. Compiler, layout, routing, scoring, eligibility, database schema, and generated site output stay unchanged.

**Tech Stack:** Python 3.12+, dataclasses, SQLAlchemy JSONB publisher, pytest, Ruff.

## Global Constraints

- Cross-module class (b): Analytics PR targets `main`; paired App PR targets `development`; PRs cross-reference and land together.
- Keep outer dossier `schemaVersion: 1`; `decisionFlow` is additive and optional.
- Runtime versions are authoritative: flow schema `1`, compiler `1.2.0`, layout `5`, routing `1`.
- Omit `decisionFlow` for missing patterns or failed existing eligibility. Never emit `null` or a synthetic empty flow.
- Emit `build_decision_flow_from_patterns()` output unchanged. Do not duplicate compiler, scoring, eligibility, layout, or routing logic.
- No Alembic migration, production mutation, ELO change, new dependency, public-site code, or generated asset edit.
- Test execution is waived for this planning handoff. Implementation records static/contract gates; automated commands remain documented but unclaimed.

## Contract Boundary

Producer field:

```python
AthleteDossierV1 = {
    "schemaVersion": 1,
    # existing fields unchanged
    "decisionFlow": FlowchartPayload,  # optional; absent when unavailable
}
```

`FlowchartPayload` is the exact dict returned by `build_decision_flow_from_patterns()`: top-level compiler fields and `layouts`, plus its existing `decisionFlow.quality`. Do not flatten or rename `quality` in this PR.
